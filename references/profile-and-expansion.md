# 画像与条件扩展

## `profile.json` 契约

脚本接受以下字段；除 `education`、`major` 外均可省略，但字段缺失会降低筛选和解释质量。

```json
{
  "education": "本科",
  "major": "新闻传播学",
  "schoolTier": "211",
  "locations": ["四川"],
  "sectors": ["传媒", "科技"],
  "recruitTypes": ["校招"],
  "keywords": ["品牌", "内容运营"],
  "excludeKeywords": ["劳务派遣", "销售"],
  "acceptUnrestrictedMajor": true,
  "acceptRelocation": false,
  "maxQueries": 48,
  "minimumResults": 20,
  "resultLimitPerQuery": 30,
  "scanLimit": 1500,
  "majorBeamWidth": 8,
  "majorBeamDepth": 5,
  "majorMaxCandidates": 24
}
```

### 字段说明

| 字段 | 含义 | 规则 |
| --- | --- | --- |
| `education` | 最高学历 | 原样交给 CLI；用于学历门槛过滤 |
| `major` | 专业原名 | 保留用户原文，再由映射扩展 |
| `schoolTier` | 院校层级 | 用于解释和辅助排序，不作硬性录取判断 |
| `locations` | 意向省、市或区域 | 数组；省份与区域会展开为城市 |
| `sectors` | 意向行业 | 映射为 CLI 的标准行业枚举 |
| `recruitTypes` | 招聘类型 | 映射为 `campus`、`social`、`intern` |
| `keywords` | 用户关注的岗位词 | 原样保留并逐个查询 |
| `excludeKeywords` | 明确排除项 | 查询后在本地应用，不传给 CLI |
| `acceptUnrestrictedMajor` | 是否接受不限专业 | 默认 `true` |
| `acceptRelocation` | 是否接受画像地区之外地点 | 默认 `false`；当前不会自动新增跨区查询 |
| `maxQueries` | 最大查询次数 | 默认 48，范围 1–120 |
| `minimumResults` | 满意的去重岗位数 | 默认 20；仅用于提前停止 |
| `resultLimitPerQuery` | 每条查询返回上限 | 默认 30，范围 1–100 |
| `scanLimit` | 每条查询扫描上限 | 默认 1500，范围 100–5000，且不得小于返回上限 |
| `majorBeamWidth` | 专业树每层保留的候选宽度 | 默认 8，范围 1–64 |
| `majorBeamDepth` | 专业树最大扫描深度 | 默认 5，范围 0–12 |
| `majorMaxCandidates` | 专业树最终候选上限 | 默认 24，范围 1–200 |

未知字段不会写入 `profile` 快照，并会产生警告。这样可以避免把误填的联系方式、账号或完整简历带入运行记录和 HTML 报告。

## 确定性候选扩展

地区和行业规则源为 [expansions.json](expansions.json)，专业层级源为
[major-tree.json](major-tree.json)。它们为 AI 提供可复用、可审计的候选和基线计划，
不是必须逐条执行的固定方案。

1. **专业**：从输入专业匹配一个或多个起点，在“具体专业 → 专业类 → 学科门类 →
   文科/理工科等大类 → 专业不限”的树上做 Beam 扫描，并可通过显式关联边探索
   有依据的相邻专业。
2. **地区**：城市原文直接使用；省级行政区展开为该省城市；经济圈或大区展开为版本化城市清单。
3. **行业**：别名映射为 CLI 标准行业；无法映射的输入产生警告，不伪造标准行业。
4. **招聘类型**：常用中文和英文别名映射为 CLI 枚举。
5. **关键词**：用户原词优先，再加入 Beam 路径节点携带的典型岗位词。

每个专业候选包含节点、类别、得分、树路径、扫描路径和查询词。例如：

```text
专业不限 → 文科/人文社科 → 文学 → 中国语言文学类 → 汉语言文学
```

Beam 每层只保留 `majorBeamWidth` 个高分候选，并受深度与总候选数限制。向上放宽后
不会自动回落到无关兄弟学科；跨专业探索只能走 `relatedEdges` 中显式声明的关联边。

父子关系只表示分类包含和逐级放宽，**不表示同一父节点的专业彼此相似或可以互相
报考**。例如计算机类与土木类同属工学，Beam 不会因此从计算机自动进入土木。

`relatedEdges` 也只表示值得检索验证的关系：

- `search-overlap`：招聘文本中经常出现交叉专业口径；
- `skill-transfer`：能力或岗位职责存在迁移可能。

两类边都必须有权重和人工可读理由，不能当作资格结论。是否满足专业代码要求仍以
招聘公告为准。

## 向量召回

当前默认不依赖外部 embedding 服务。字符串精确匹配和词面匹配足以覆盖目录中已经
登记的标准名称与别名，避免模型版本、网络和随机性影响可复现性。

Beam 接口支持传入 `semanticScores`，供未来或外部流程用向量检索召回未知专业的
候选起点，但遵守以下边界：

- 向量只参与 seed recall，不创建新的树边；
- 向量召回的起点标记为 `kind=semantic`，不标记为精确命中；
- 语义相似不等于岗位资格兼容，不能直接触发“可报考”结论；
- 正式查询前由 AI 结合节点路径、显式关联边和真实岗位文本决定是否采用；
- 无向量服务时行为保持确定、可离线测试。

脚本为基线查询生成稳定 ID，顺序由阶段、原始输入顺序、Beam 得分及树中稳定顺序
决定。同一画像和同一规则版本必须产生相同基线。AI 可以根据用户目标和实际结果
选用、重组或补充查询，并通过 `guoyang-search-strategy/v1` 留下理由。

## 基线查询阶段

为避免无界笛卡尔积，计划使用分阶段组合：

| 阶段 | 主要条件 | 用途 |
| --- | --- | --- |
| `exact` | 原专业 + 原始/首选地区 + 意向行业 | 先找最贴合岗位 |
| `location-expanded` | 原专业 + 省内或区域城市 | 用较宽查询覆盖省级地区内各城市，避免与行业形成无界组合 |
| `major-beam` | Beam 候选专业 + 地区 + 行业 | 覆盖上位专业、具体子专业和显式关联专业 |
| `role-expanded` | 岗位关键词 + 地区 + 行业 | 覆盖岗位按职责而非专业标注的情况 |
| `sector-expanded` | 原专业 + 专业树候选的相关行业 | 在用户意向行业外补充与专业高度相关的标准行业 |
| `unrestricted-major` | “专业不限”关键词 + 地区 + 行业 | 用户接受不限专业时补充 |

各阶段按 `maxQueries` 截断。未提供 AI 策略时，执行器可用它作为兜底流程；正常技能流程应由 AI 从中选择少量有区分度的查询，并根据首轮结果迭代。

## 人工补充

当专业没有精确命中专业树节点时：

- 仍使用专业原文查询；
- 基线计划明确显示“未命中专业树”，模糊候选只供 AI 判断，不自动生成扩展查询；
- AI 可以结合用户经历提出岗位方向假设，必要时请用户确认；
- AI 自主补充的专业、岗位词或行业必须在策略文件中说明理由，不能冒充版本化确定性扩展。
