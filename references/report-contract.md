# 岗位报告与日志契约

## 输出分层

每次生成两份文件：

1. **用户 HTML**：只展示岗位清单和投递所需信息。
2. **旁路日志**：默认与 HTML 同名并使用 `.log.json` 后缀，保存完整机器数据、
   查询证据和历史比较。

HTML 不嵌入 JSON、不链接日志，也不展示画像、AI 策略、专业树路径、查询轨迹、
扫描状态、内部岗位键或历史比较明细。

## 用户 HTML

页面只包含：

- “优先投递 / 可以尝试 / 继续观察”三个有结果的分组；
- 企业名和岗位名；
- 地点、学历、专业、招聘类型、用工性质、招聘人数、薪资和截止时间中已有的字段；
- 针对该岗位的推荐理由、需要核验的风险和下一步动作；
- 官方或来源投递入口；
- 一句提醒用户以投递页面为准的声明。

没有岗位的分组不显示。命中硬排除条件、被 AI 排除或未通过校验的岗位不出现在
HTML 中。页面不显示查询数量、失败来源、抓取时间、AI 置信度或内部评分。

## 旁路日志

日志格式标识为 `guoyang-report/v1`，保存：

- 规范化画像；
- CLI 版本、策略、专业树 Beam 候选与查询轨迹；
- 来源覆盖、失败信息和扫描量；
- AI 的完整分析、自定义章节和岗位取舍；
- 可见及被排除岗位；
- 历史新增、变化、再次检出和本轮未再检出。

岗位记录至少保留：

- `stableKey`、来源标识和岗位原始事实；
- `recommendation.bucket`、`score`、`reasons`、`risks` 和 `source`；
- `discovery.queryIds`、首次命中及最近一轮命中信息。

后续报告通过 `--previous-log` 读取历史日志。生成器仍兼容读取拆分前、带内嵌 JSON
的旧 HTML，但新 HTML 不再承担机器解析职责。

## AI 排序与分档

AI 综合用户画像、岗位事实、来源质量和职业策略作出分档，不要求遵循固定加减分
公式。它为每个岗位提供 0–100 的相对优先级、分档、理由、风险和下一步动作；该
数字只用于内部排序，不显示在用户 HTML，也不代表录取概率。

正式报告默认要求 AI 覆盖所有非硬排除岗位。只有
`unassessedPolicy=fallback` 时才允许在日志中标记并使用代码兜底判断。

## 校验要求

校验器同时检查 HTML 和日志：

- HTML 无脚本、无内嵌机器数据、无内部稳定键和查询信息；
- HTML 岗位卡片数量、企业名和岗位名与日志一致；
- HTML 只包含安全的 `http/https` 投递链接；
- 日志 schema、时间、岗位稳定键、分档、来源和统计计数合法；
- AI 分析只引用本次证据集中存在的岗位；
- 历史变化和可见岗位计数一致。
